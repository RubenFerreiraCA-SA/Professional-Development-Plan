# 01. Background and Rationale

> **SECTION AT A GLANCE**
>
> Software engineering is evolving beyond traditional application development towards broader responsibilities involving automation, cloud infrastructure, artificial intelligence and platform operations. This programme responds to that evolution by establishing a structured pathway for expanding existing software development competencies into these engineering disciplines.

Software engineering continues to evolve beyond the design and implementation of individual applications. Modern software delivery increasingly depends on automated build and deployment systems, cloud infrastructure, secure operational practices, reliable observability and reusable developer services.

As organisations adopt cloud-native architectures and AI-enabled systems, software engineers benefit from understanding how applications are built, deployed, secured, monitored, scaled and maintained throughout their operational lifecycles. These developments create both opportunities and challenges for professionals whose experience is concentrated in application development.

The programme is established as a structured professional development initiative to extend existing software engineering capability into four complementary disciplines: DevOps Engineering, Cloud Engineering, AI Engineering and Platform Engineering. Its design recognises their technical interdependence and seeks to build competence progressively rather than presenting an unrelated collection of short courses.

The intended outcome is broader engineering capability, with particular emphasis on applying and integrating these disciplines within modern platform engineering environments.

# 02. Programme Purpose

> **SECTION AT A GLANCE**
>
> The programme aims to develop a software engineer capable of contributing across the complete software delivery and operational lifecycle, with particular emphasis on Platform Engineering. It combines structured learning, practical engineering experience and recognised professional certifications to support a measurable transition towards broader technical responsibilities.

The primary purpose is to develop the knowledge, practical skills and professionally recognised competencies needed to transition from an application-focused software engineering role towards broader engineering responsibilities, particularly Platform Engineering.

The programme combines structured theoretical study, industry-standard tooling, practical technical assignments, professional certification preparation and a cumulative engineering project.

Emphasis is placed on demonstrated engineering competence: the participant should be able to identify a technical problem, select appropriate solutions, implement and validate those solutions, troubleshoot failures and justify architectural choices.

**Central objective:** Develop an engineer capable not only of creating software applications, but also of contributing to the systems through which software is built, delivered, operated and continuously improved.

# 03. Programme Philosophy

> **SECTION AT A GLANCE**
>
> The programme is built around four interconnected disciplines: DevOps Engineering establishes software delivery and automation capabilities; Cloud Engineering develops infrastructure expertise; AI Engineering introduces intelligent systems and workflows; and Platform Engineering integrates these competencies into reusable, secure and developer-friendly engineering services.

## 03.1 DevOps Engineering — The Delivery Foundation

DevOps Engineering concerns the practices and tools through which software is integrated, tested, packaged, delivered, deployed and operated. It emphasises automation, repeatability, collaboration, feedback and reliability.

DevOps appears first because its techniques can offer immediate practical value to an existing developer. The curriculum addresses repository management, containerisation, CI/CD, infrastructure as code, GitOps and observability. These capabilities support the disciplines that follow.

## 03.2 Cloud Engineering — The Infrastructure Foundation

Cloud Engineering concerns the design, provisioning, security, configuration and management of computing infrastructure and cloud services.

Building on the DevOps foundation, the participant develops deeper understanding of computing, networking, identity, cloud architecture, resilience and service integration. The proposed syllabus principally uses Amazon Web Services (AWS), while teaching transferable cloud principles.

## 03.3 AI Engineering — The Intelligence Foundation

AI Engineering concerns the design, integration, evaluation, deployment and operation of software incorporating artificial intelligence.

This programme emphasises **applied AI engineering**, rather than foundational machine learning research. Topics include language model integration, retrieval approaches, agentic workflows, orchestration, evaluation, security and AI operations.

## 03.4 Platform Engineering — The Integration Discipline

Platform Engineering integrates infrastructure, delivery automation, security, reliability and developer experience into reusable, standardised and self-service capabilities.

An internal developer platform is treated as a product for its developer users. Its purpose is to reduce avoidable engineering complexity, improve delivery consistency, establish secure defaults and allow application teams to focus on business functionality.

## 03.5 How the Disciplines Connect

- **DevOps Engineering:** how software moves from development to dependable delivery.
- **Cloud Engineering:** the infrastructure and services on which software runs.
- **AI Engineering:** intelligent capabilities within applications and engineering workflows.
- **Platform Engineering:** reusable developer-facing products combining the preceding capabilities.

# 04. Platform Engineering Specialisations

> **SECTION AT A GLANCE**
>
> Platform Engineering encompasses six principal specialisations: Infrastructure, Developer Experience, Security, Reliability, Data and Platform Leadership. The programme develops a common technical foundation across these areas, enabling participants to pursue further specialisation according to their interests, demonstrated competencies and organisational requirements.

Platform Engineering encompasses a variety of roles with overlapping technical and product responsibilities. The programme introduces six broad specialisations as a career-development framework:

| Specialisation | Primary focus |
| --- | --- |
| Infrastructure Platform Engineering | Cloud architecture, infrastructure automation, Kubernetes and provisioning |
| Developer Experience Platform Engineering | Developer portals, reusable templates, golden paths, tooling and self-service workflows |
| Security Platform Engineering | Identity and access, secrets, policy enforcement and software supply-chain security |
| Reliability Platform Engineering | Observability, SLOs, incident response, performance and resilience |
| Data Platform Engineering | Reusable data infrastructure and self-service data capabilities |
| Platform Engineering Leadership | Platform strategy, product management, adoption and engineering effectiveness |

The programme does **not** claim specialist mastery across all six areas. It develops a shared technical foundation and creates opportunities for further specialisation based on professional goals, demonstrated capability and organisational requirements.

The final discipline gives particular practical attention to infrastructure, developer experience and reliability, while introducing related security, data-platform and platform-product concepts.

# 05. Programme Objectives

> **SECTION AT A GLANCE**
>
> The programme seeks to broaden technical expertise, strengthen architectural decision-making, develop practical proficiency in modern engineering technologies, establish applied AI and cloud-native capabilities, and obtain independent professional recognition. Its emphasis is on demonstrable professional competence rather than theoretical knowledge alone.

The programme seeks to:

1. **Broaden technical competence:** Extend application development skills into infrastructure, delivery automation and production operations.
2. **Develop practical proficiency:** Build working systems with relevant industry-standard technologies.
3. **Strengthen architecture capability:** Evaluate trade-offs involving security, reliability, performance, maintainability and cost.
4. **Develop cloud-native capability:** Apply containers, infrastructure automation, cloud services and Kubernetes.
5. **Develop applied AI capability:** Integrate and evaluate AI within software and engineering workflows.
6. **Develop platform engineering capability:** Create reusable, secure, observable and developer-friendly engineering services.
7. **Seek independent professional recognition:** Pursue relevant industry-recognised qualifications.
8. **Produce verifiable evidence:** Maintain a portfolio of practical work, technical documentation, design decisions and certification achievements.

# 08. Certification Strategy

> **SECTION AT A GLANCE**
>
> Industry-recognised certifications provide independent validation of selected technical competencies developed throughout the programme. Certification preparation is aligned with practical learning and professional relevance. Specific examination objectives, costs, deadlines and achievements are managed separately, with individual PDP obligations clearly distinguished from general programme requirements.

Certifications complement practical training by providing external validation of selected competencies. Certification decisions should follow four principles:

- **Relevance:** Align with demonstrated programme skills and employer needs.
- **Practical competence:** Reinforce genuine technical proficiency, not memorisation alone.
- **Progressive attainment:** Match prerequisites and examination scope to the learning sequence.
- **Independent validation:** Use official awarding bodies and retain verifiable credentials.

Neither module completion nor practical project completion automatically implies that an external certification has been awarded. Current exam eligibility, prices, exam versions and credential status must be verified before booking.

The details are governed by the [Certification Roadmap](06_Certification_Roadmap.md) and [Certification and Evidence Tracker](03_Certification_and_Evidence_Tracker.md).

# 09. Teaching and Learning Methodology

> **SECTION AT A GLANCE**
>
> The programme uses a structured, self-directed learning model requiring approximately 8–10 hours per instructional week. Learning combines conceptual study, guided exercises, independent practical assignments, troubleshooting and technical documentation. Practical application is prioritised to develop transferable engineering skills and problem-solving competence.

The programme is delivered through self-directed learning structured around the weekly module specifications.

Each week should incorporate, as relevant:

1. **Conceptual understanding:** Principles, terminology and relevant architecture.
2. **Guided application:** Official documentation, tutorials and controlled demonstrations.
3. **Independent practical work:** Engineering tasks completed with progressively less guidance.
4. **Verification and troubleshooting:** Evidence that the implementation works and failures can be explained.
5. **Documentation and reflection:** Outputs, decisions, obstacles, lessons and improvement opportunities.

The expected commitment is **8–10 hours per instructional week**, recognising that technical complexity and prior experience may change actual effort. The learning model seeks transferable problem-solving skill and practical implementation rather than passive participation.

Application to work environments must comply with organisational policies and authorisations. Public training environments, synthetic data and non-confidential test infrastructure should be used where employer or client access is not appropriate.

# 10. Assessment Philosophy

> **SECTION AT A GLANCE**
>
> Competence will be evaluated through demonstrable technical outcomes rather than participation alone. Assessment evidence may include functioning implementations, completed laboratory assignments, infrastructure configurations, automated workflows, architectural decisions and professional certifications. Formal assessment criteria and completion requirements are defined within the supporting assessment framework.

Assessment measures the ability to implement, explain and validate engineering work. Appropriate evidence may include code, infrastructure definitions, deployment workflows, automated tests, monitoring dashboards, runbooks, design decisions, written explanations and practical demonstrations.

Depending on the module, assessment should consider:

- Correctness and functional operation
- Security and accepted engineering practice
- Repeatability, maintainability and documentation
- Understanding of architecture and technical trade-offs
- Troubleshooting and validation capability
- Practical usefulness of the resulting solution

Detailed module rubrics, completion conditions and evidence standards are maintained in the [Assessment Framework](07_Assessment_Framework.md).

Formal employer reviews, external examinations and sign-off meetings are separate from instructional weeks. Where a module allocates assessment weighting to practical labs, those labs remain part of its instructional curriculum.

# 11. Practical Project Framework

> **SECTION AT A GLANCE**
>
> A cumulative, organisation-neutral Internal Developer Platform project provides the practical foundation for integrating competencies across all four disciplines. The project evolves from automated software delivery and cloud infrastructure into AI-enabled capabilities and reusable developer services, culminating in a demonstrable technical portfolio.

A cumulative **Generic Internal Developer Platform** serves as a practical example of the four disciplines working together.

The project is designed to explore a reusable environment through which application developers can build, test, deploy, monitor and operate applications using secure standardised workflows and self-service capabilities.

It is **organisation-neutral** and must not rely on proprietary employer systems, confidential client information or unauthorised infrastructure.

## 11.1 Progressive Project Development

**DevOps:** Create an application repository; containerise services; build automated integration and delivery workflows; define infrastructure with code; implement GitOps and monitoring.

**Cloud:** Improve infrastructure architecture, IAM, networking, security, managed services, scalability and resilience.

**AI:** Evaluate and incorporate appropriate intelligent capabilities, potentially including operational analysis, documentation support, diagnostics or workflow assistance.

**Platform:** Integrate the engineering capabilities into reusable developer-facing services, templates and self-service workflows with clear security and reliability boundaries.

## 11.2 Expected Evidence

Evidence should include reproducible implementations, working automation, infrastructure and deployment configuration, monitoring and observability, technical documentation, architecture decisions and practical demonstrations.

The detailed scope, implementation choices, acceptance tests and submission requirements belong in [Capstone Project Specification](08_Capstone_Project.md), not this charter.
