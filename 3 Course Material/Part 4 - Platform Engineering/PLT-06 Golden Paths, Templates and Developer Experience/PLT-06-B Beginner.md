## MODULE PLT-06-B — GOLDEN PATHS, TEMPLATES AND DEVELOPER EXPERIENCE — BEGINNER

### 1. Topic and Scope

**In scope for this level:** Foundations of golden paths and developer experience. You explain the three kinds of cognitive load (intrinsic, extraneous, germane), define a golden path as the easiest supported route rather than a cage, write a short golden-path specification, and structure the first thirty minutes of onboarding as an entry document you test on a clean machine.

**Out of scope:** Template engineering, scaffolding commands and guardrail design (Intermediate), discoverability, status commands and measurement protocols (Professional), independent trials and statistics (Expert), and the Harbour first-use guide (Project Document).

**Self-assessment fit:** Choose this level in [2.2 Topic Self Assessment](../../../2%20PDP%20Development/2.2%20Topic%20Self%20Assessment.md#plt-06--golden-paths-templates-and-developer-experience) when this matches your current ability: *Explain golden paths, templates and developer experience.* Typical starting point: You use internal tooling daily but have not written onboarding material for someone else.

### 2. Learning Objectives

1. Classify three Harbour onboarding frustrations as intrinsic, extraneous or germane cognitive load and say which the platform can remove.
2. Define a golden path and explain how it differs from a mandate, a template and a cage, giving one example of an escape hatch.
3. Write a golden-path specification with audience, outcome, steps, supported variations and a measurable success condition.
4. Order the first thirty minutes of an entry document (goal, prerequisites, one command, expected result, what next, where to get help) and justify the order.
5. Prepare the evidence needed for **PRJ-089**: a clear entry guide for creating or onboarding a sample service, validated by running it verbatim on a clean environment with every improvised step recorded.

### 4. Knowledge Assessment

**Task:** Write an entry document for a tool you know, then follow it verbatim on a clean container or account. List every command you had to improvise and rewrite the document to remove each one.

**Pass criteria:** The guide runs unchanged to the stated success condition; improvisations are listed honestly; each fix is made in the document; the audience and assumed knowledge are explicit.

Record the result in your Learning Progress Record. Passing the knowledge assessment does **not** by itself complete the module — the project assignment below is also required for a project-linked pathway.
