## MODULE PLT-07-P — PLATFORM INTEGRATION, RELIABILITY AND EVOLUTION — PROFESSIONAL

### 1. Topic and Scope

**In scope for this level:** Demonstrating an operable platform end to end. You turn evidence into a reliability and cost backlog, pick failure injections from a menu rather than doing them all, run game days led by someone else, set SLOs for the platform itself, check integration seams, rehearse the demonstration run, and record achieved, deferred and learn-next items.

**Out of scope:** Walking the basic path (Beginner to Intermediate), long-term platform evolution, deprecation and governance (Expert), and the Harbour acceptance-evidence presentation (Project Document).

**Self-assessment fit:** Choose this level in [2.2 Topic Self Assessment](../../../2%20PDP%20Development/2.2%20Topic%20Self%20Assessment.md#plt-07--platform-integration-reliability-and-evolution) when this matches your current ability: *Demonstrate an operable platform experience end to end.* Typical starting point: You can run the path and now need to show it survives failure and that you can prove recovery.

### 2. Learning Objectives

1. Select two failure injections (for example a bad promotion and an expired credential), state expected symptoms and recovery before injecting, and compare results afterwards.
2. Define two platform SLOs (for example status-command availability and promotion latency) with indicators, targets and how they are measured.
3. Run the integration-seam checklist and record each seam as evidenced, partial or missing.
4. Rehearse a thirty-minute demonstration run of show that maps each required point to evidence and states what is simulated.
5. Prepare the evidence needed for **PRJ-095**: a bounded failure and recovery scenario with the evidence a second developer would need, plus a reflection record of achieved, deferred and learn-next items.

### 4. Knowledge Assessment

**Task:** Have another person inject a failure from a card while you recover using only the documentation. Present the timeline, the evidence a second developer would need, and your reflection record.

**Pass criteria:** Predictions were written before injection; recovery is evidenced rather than asserted; SLOs are measurable; the reflection record separates achieved, deferred and learn-next honestly.

Record the result in your Learning Progress Record. Passing the knowledge assessment does **not** by itself complete the module — the project assignment below is also required for a project-linked pathway.
