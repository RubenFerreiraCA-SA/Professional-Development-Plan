# Final Project Checklist — Harbour IDP

This page is the **living specification** for the recommended Final Project: one running system (**Harbour**) that grows into a small **Internal Developer Platform**.

Tick a row only when its **acceptance criterion** is met. Capability descriptions and evidence lists support that judgement — they are not a substitute for it.

| Related artefact | Question it answers |
| --- | --- |
| [Capacity Planner](../2%20PDP%20templates/PDP%20Capacity%20Planner.xlsx) | When do I expect to complete it? |
| [Progress and Evidence Log](../2%20PDP%20templates/2.4%20Progress%20and%20Evidence%20Log.md) | What have I learned and completed? |
| **This checklist** | What can my platform demonstrably do? |

The project is **recommended, not compulsory**. Personalise scope in your [Personal Profile](../2%20PDP%20templates/2.1%20Personal%20Profile.md) and Capacity Planner (`Include = Yes/No`). Only **in-scope** rows count toward your Final Project.

## Scope legend

| Scope | Meaning |
| --- | --- |
| **Required** | Part of the recommended Final Project. Exclude only if your PDP explicitly drops it (`Include = No`) and you record the adaptation. |
| **Optional** | Never required for Final Project completion. Include only if your PDP says so. Leaving it unticked is success, not a gap. |
| **Optional for Final Project (vendor)** | **D08** stays Chapter 8 of the **full** DevOps curriculum (see [D00](../3%20Course%20Detail/3.1%20DevOps/D00%20DevOps%20Syllabus.md)). For the Final Project only, you may mark `N/A` if you meet an equivalent ops bar on your D07 stack and document the substitution — that satisfies personalised IDP acceptance, not “full DevOps curriculum complete.” |

**Curriculum vs Final Project:** Completing the full published syllabus (e.g. all eight DevOps chapters) and meeting personalised Final Project requirements are related but separate. This checklist judges the latter.

**Learning vs platform:** You may mark a module **Complete** in the [Progress Log](../2%20PDP%20templates/2.4%20Progress%20and%20Evidence%20Log.md) when its learning assessment is done, even if this checklist row is still open.

**Status values:** `☑` met · `☐` not yet · `N/A — out of scope` · `Adapted: …`

## Progressive specification

### DevOps

| ☐ | Scope | Module | Platform gains | Acceptance criterion (pass when…) | Evidence to keep |
| --- | --- | --- | --- | --- | --- |
| ☐ | Required | **D01** | Governed repo: ownership, protected default branch, contribution path, secret hygiene | A newcomer using only the repo docs can open a change to a sensitive path and name who must approve it; an unauthorised direct push to the default branch is rejected **or** the enforcement gap is documented with a compensating control | Structure, CODEOWNERS/approvals (or gap note), ADR, reviewed change record, secret-scanning demo with fabricated data |
| ☐ | Required | **D02** | Safe history practice for Harbour | From a deliberate messy state on a **disposable** clone, restore using only your written recovery notes without rewriting shared `main` | Recovery notes, before/after refs, regression investigation (e.g. bisect) write-up |
| ☐ | Required | **D03** | Harbour API (+ dependency) as a hardened container contract | Someone unfamiliar with the stack builds and runs the service from repo instructions alone and receives a healthy response; the image they run is identified by **digest** | Dockerfile, Compose (or equivalent), health endpoint, digest, build instructions, SBOM/vuln notes |
| ☐ | Required | **D04** | Reviewed change → tested immutable artifact → promotion | A failing check blocks merge; a passing change yields a digest-addressed artifact traceable to the merge commit; promotion selects that digest (not a floating mutable tag) | Pipeline definition, failed-gate proof, provenance record, promotion log |

| ☐ | Required | **D07** | Vendor-neutral observability on the request path | A responder who did not plant the fault answers your documented incident questions using **only** telemetry and the runbook, then verifies remediation | Telemetry architecture, instrumented path, SLIs/SLOs, alert + runbook, investigation write-up |

## Final demonstration checklist

Complete the **Required** items for your in-scope pathway. **Optional** items apply only when that scope was included; leaving them blank or `N/A` does **not** make the Final Project incomplete.

### Required for Final Project completion

| ☐ | Demonstration |
| --- | --- |
| ☐ | Another developer can start from the template or Harbour docs and contribute safely |
| ☐ | A reviewed change triggers automated build/test and produces a traceable artifact |
| ☐ | An approved environment is selected or provisioned through code and the service is deployed |
| ☐ | Health is visible; a failure can be investigated and recovered from with a documented path |
| ☐ | Security and access controls for the demo are explained (gaps are honest) |
| ☐ | Repo has no real secrets; limitations and cost choices are written down |
| ☐ | Short architecture decisions + PDP reflection (achieved / deferred / learn next) |

### Optional — only if in your PDP

| ☐ | Demonstration | When it applies |
| --- | --- | --- |
| ☐ | AI component: purpose, evaluation, limits and safeguards explained | AI track included (`A01`–`A03`) |
| ☐ | Vendor monitoring onboarding story (second team/service) | Final Project includes the Datadog/`D08` track (still a full-curriculum chapter either way) |

Align with the [completion standard](1.4%20Final%20Project.md). Module Practical Assessments remain the detailed bar where published.

## How the three progress views work together

1. **Plan** dates and scope in the Capacity Planner (`Include`, hours/week, milestones).
2. **Record** learning sessions and links in the Progress and Evidence Log; mark learning **Complete** when the module assessment is demonstrated (checklist may still be open).
3. **Accept** a row here only when its acceptance criterion is true — independently of Progress Log Complete.
4. If pace slips, change the Capacity Planner; do not “pass” this checklist to match the calendar.
