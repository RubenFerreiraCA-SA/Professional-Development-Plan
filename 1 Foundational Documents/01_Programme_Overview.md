# Programme Overview

## Purpose

This framework helps **any software developer create their own Professional Development Plan (PDP)** with a focus on **Platform Engineering and its enabling disciplines**.

It provides a **recommended 64-week learning pathway**, supporting study materials, practical exercises and guidance that developers can adapt to their experience, goals and available time.

## Four connected disciplines

| Discipline | Weeks | Contribution |
| --- | --- | --- |
| **DevOps Engineering** | 1–15 | Version control, containers, CI/CD, infrastructure as code, GitOps and observability |
| **Cloud Engineering** | 16–31 | Linux, networking, cloud services, infrastructure and architecture |
| **AI Engineering** | 32–43 | Applied LLMs, agentic workflows and LLM operations |
| **Platform Engineering** | 44–64 | Kubernetes, developer self-service, internal platforms and reliability |

**Why this order?** DevOps establishes the delivery foundation. Cloud adds the infrastructure. AI introduces intelligent capabilities. Platform Engineering brings them together into services that make development easier and safer.

## Platform Engineering specialisations

Platform Engineering spans several related areas:

| Specialisation | Focus |
| --- | --- |
| Infrastructure | Cloud platforms, provisioning and orchestration |
| Developer Experience | Golden paths, templates, portals and self-service |
| Security | Identity, secrets, policy and supply-chain controls |
| Reliability | Observability, resilience, SLOs and incident response |
| Data | Shared data infrastructure and services |
| Platform Leadership | Platform strategy, adoption and product thinking |

The framework provides a foundation across these areas; it does not claim to produce an expert in every specialisation.

## What success looks like

By the end, a learner should be able to automate application delivery, provision cloud infrastructure, integrate appropriate AI capabilities, operate Kubernetes workloads and demonstrate a functioning **Internal Developer Platform**.

The proof is practical work—code, configurations, labs, working deployments and clear technical decisions—not the number of courses watched.
